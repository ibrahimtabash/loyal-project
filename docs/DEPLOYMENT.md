# تشغيل ونشر رِجعة

## المتطلبات

Laravel 12 + Inertia 2 + React 19 + Vite 7. PHP 8.2+ مع Composer وNode 22. اختر PHP حديثاً ومحدّثاً على خادم الإنتاج. النسخة المحلية تستخدم SQLite؛ الإنتاج المستهدف PostgreSQL مع `pdo_pgsql`.

`php artisan serve` يضبط مجلد الرفع المؤقت على `storage/app/private/upload-tmp` داخل المشروع، بحد 4M للملف و8M للطلب. تُرسل تحذيرات PHP إلى سجل الخادم بدلاً من تلويث استجابة JSON. عند استخدام PHP-FPM أو Apache اضبط `upload_tmp_dir` إلى مجلد قابل للكتابة لحساب PHP، و`upload_max_filesize=4M` و`post_max_size=8M` و`display_errors=Off` و`log_errors=On` في إعدادات PHP الخاصة بالخادم، ثم أعد تشغيله. لا تكفي إعدادات Laravel لتغيير مرحلة تحليل ملفات multipart التي تسبق تشغيل التطبيق.

## تشغيل محلي جديد

```sh
composer install
npm ci
cp .env.example .env
php artisan key:generate
php artisan migrate
php artisan db:seed --class=DemoStoreSeeder
npm run build
php artisan serve
```

لا تعِد نسخ `.env` أو توليد المفتاح إذا كانت البيئة مهيأة مسبقاً. على Windows استخدم `Copy-Item .env.example .env` في التشغيل الأول. PHP الموجود في الجهاز وقت التنفيذ هو `D:\xampp\php\php.exe`؛ أضف مجلده إلى PATH في الجلسة أو استخدم المسار الكامل. `composer dev` يشغّل Laravel، و`npm run dev` في نافذة أخرى يشغّل تحديث الواجهة أثناء التطوير. تشغيل البناء يكفي للمعاينة دون Vite dev server.

- `/`: الرئيسية الجديدة.
- `/s/dar`: متجر عرض ببيانات وصور تجريبية.
- `/register`: إنشاء حسابك ومتجرك الخاص.
- `/store`: الهوية، الصورة، المدينة، العملة، رقم واتساب ورسوم التوصيل والنشر.
- `/products`: إضافة وتعديل المنتجات ورفع الصور.
- `/orders`: تفاصيل الطلبات وانتقالاتها.
- `/dashboard`: إحصاءات الطلبات والعملاء والمبيعات المسلّمة.
- `/customers`: قائمة العملاء والبحث والتصفية وإضافة العملاء.
- `/customers/{id}`: ملف العميل ومحفظته وسجل النقاط والملاحظات والطلبات والاستبدال.
- `/rewards`: إنشاء المكافآت وصورها وتكلفتها بالنقاط والكمية المتاحة.

عند ترقية نسخة Laravel السابقة: نفّذ `php artisan migrate` ثم `php artisan loyalty:sync-orders` لربط الطلبات السابقة بمحافظ العملاء. الأمر لا يستورد Supabase؛ راجع أي أرصدة افتتاحية قبل استخدامه على بيانات مستوردة كي لا تُحتسب نقاط الطلبات ضمنها مرتين. `php artisan db:seed --class=DemoRewardsSeeder` يضيف مكافآت عرض لمتجر دار المحلي فقط، ولا ينشئ حسابات أو أرصدة عملاء.

لا توجد كلمة مرور مشتركة لحساب العرض. استقبال طلباته معطّل لعدم وجود رقم واتساب حقيقي. أنشئ حسابك الخاص من `/register` للتجربة الكاملة. بيانات العرض مسموحة في local/testing فقط؛ `db:seed` العادي لا ينشئ حسابات افتراضية.

## إعداد الإنتاج

1. أنشئ بيئة staging وقاعدة PostgreSQL منفصلة عن Supabase الحالي. اختبر النقل إن وُجدت بيانات حقيقية؛ لا تشغّل `migrate:fresh` على بيانات عملاء.
2. اضبط `APP_ENV=production`, `APP_DEBUG=false`, `APP_URL=https://your-domain`, `SESSION_SECURE_COOKIE=true`, `SESSION_HTTP_ONLY=true`, `SESSION_SAME_SITE=lax`. خزّن `APP_KEY` وكلمات المرور خارج Git. اضبط اتصال PostgreSQL وTLS حسب مزود قاعدة البيانات.
3. وجّه جذر Nginx/Apache إلى `public/` حصراً. شغّل PHP-FPM، وليس `artisan serve`. اضبط الوكيل الموثوق حسب الشبكة الفعلية إذا استخدمت موازن حمل.
4. اجعل `storage/` و`bootstrap/cache/` قابلين للكتابة لحساب التطبيق فقط. ملفات الصور الحالية على قرص محلي دائم؛ لا تستخدم قرص حاوية مؤقتاً. عند تعدد الخوادم، انقل MediaController والتخزين إلى S3 مشترك واختبر سياسة العرض.
5. ثبّت من lockfiles: `composer install --no-dev --optimize-autoloader`, `npm ci`, `npm run build`. نفّذ النسخة الاحتياطية، ثم `php artisan migrate --force`, `php artisan optimize`.
6. جهّز النسخ الاحتياطي لقاعدة البيانات والصور واختبر الاسترجاع. راقب `/up` والأخطاء ومساحة التخزين. الجلسات وحدود الطلبات تستخدم قاعدة البيانات محلياً؛ اضبط Redis مشتركاً إن انتقلت لعدة خوادم.
7. جرّب حسابين منفصلين، الطلب من هاتف فعلي، الشبكة البطيئة، رفض الملفات، تغيّر الأسعار، وإعادة إرسال الطلب. راجع التصميم على 390px و768px و1440px والتباين والتنقل بلوحة المفاتيح.

لم تُنشر هذه النسخة على خادم خارجي. نقل الحسابات والبيانات، البريد واستعادة كلمات المرور، ومراجعة الأعمال المتبقية موثقة في `ARCHITECTURE.md` ويجب حسمها قبل اعتماد الإنتاج.
